## Goal — one-line outcome

Automate the engine public-surface diff between any two git refs. Commit a `scripts/public-surface.expected.json` fixture; deploy-check enforces it; a sibling script pretty-prints the diff between two refs.

## Decisions (made upfront)

### D1 — Name + kind only; defer arity/shape hints

The candidate scope mentions "arity-or-shape hint for functions (param count + return-type name) and types (top-level field names)" as Unit-1 scope. Shipping shape hints requires reading per-module `.d.ts` files for every exported name — a multi-file traverse + lightweight TS-AST parsing pass. That's a real implementation, and it gates the primary value of the artefact (catching add/remove) on getting the parsing right.

Pick: ship name + kind only in this phase. The snapshot is `{ values: ["name1", ...], types: ["TypeA", ...] }`. Add/remove drift fires on this; rename drift fires on this (a renamed name shows up as both an add + remove); shape drift (e.g. `executeSkill` gaining `casterSide`) does NOT fire here, but the existing hermetic tests in `src/test-utils/e2e/public-barrel.engine.test.ts` + the per-module `.d.ts` consumers catch shape drift via the type-checker. Shape hints can land in a follow-up phase if/when needed.

### D2 — Source is `dist/index.d.ts`, not `src/index.ts`

`src/index.ts` is the input; `dist/index.d.ts` is what consumers actually see. The Phase 50 motivator (skillLibrary missing from dist) was a build-emit issue — the source-side claim and the dist-side reality diverged. Snapshot the dist.

### D3 — Output committed at `scripts/public-surface.expected.json`, not `dist/`

`dist/` is gitignored and rebuilt every `npm run build`; a committed fixture inside `dist/` would either fight `.gitignore` or get blown away. Put the fixture at `scripts/public-surface.expected.json` alongside `deploy-check.mjs`. The fixture IS the contract — updating it is part of any public-surface-changing PR.

### D4 — Deploy-check failure mode: show the diff, not just "they don't match"

The assertion's value is in the failure message. When the snapshot diverges from the fixture, the script must print which names were added / removed so the contributor can either update the fixture (intentional change) or fix their PR (unintentional drift).

## Commit units

### Unit 1 — `scripts/snapshot-public-surface.mjs` + committed fixture

Files:
- `scripts/snapshot-public-surface.mjs` — reads `dist/index.d.ts`, parses every `export { ... } from '...';` and `export type { ... } from '...';` line, deduplicates, sorts deterministically, returns `{ values: string[], types: string[] }`. CLI mode emits to stdout as pretty-printed JSON; default mode returns the object (exposed for the deploy-check assertion to import).
- `scripts/public-surface.expected.json` — committed fixture generated by the script against the current `v0.10.0` (+ iterate additions) dist.

Verify: `node scripts/snapshot-public-surface.mjs` produces the same JSON that's committed; `git diff` shows no drift.

Commit: `feat(scripts): Phase 53 unit 1 — public-surface snapshot script + fixture`.

### Unit 2 — `scripts/deploy-check.mjs` assertion

Extend `deploy-check.mjs` after the existing tag/CHANGELOG assertion: import the snapshot function, compute the current surface, compare against `scripts/public-surface.expected.json`. On disagreement, print the diff (Added / Removed lists for both `values` and `types`) and exit 1.

Commit: `feat(scripts): Phase 53 unit 2 — deploy-check enforces public-surface fixture`.

### Unit 3 — `scripts/diff-public-surface.mjs <ref-A> <ref-B>`

`scripts/diff-public-surface.mjs` accepts two git refs as argv, uses `git show <ref>:scripts/public-surface.expected.json` to read each ref's committed fixture, prints a pretty-formatted Added / Removed (and Changed when the kind shifts — e.g. `name` was a value, became a type). Default args: `HEAD~1 HEAD` for the most recent change.

Commit: `feat(scripts): Phase 53 unit 3 — diff-public-surface tool`.
