## [mechanics] Objective function v2 — the Combat Quality Index (phase 43)

**What:** a new `combatQualityIndex` (0-1 = 0.40·spine + 0.25·arc +
0.20·width + 0.15·identity) computed and reported *beside* the old
`statusEngagement` metric, guarded by `assertLockedMechanicsFirstClass`
so no future tune can zero-weight Conviction/Surge/Dice or smuggle a
fourth term.
**Why:** `statusEngagement` graded adherence to the status-dominance
doctrine the unshackling just voided — `/deck-tuning` and
`/combat-playtest` had been optimizing a rule the game no longer has.
CQI grades *how a fight played* (does the deck's own engine run turn
over turn) instead of *whether the doctrine curve says it should win*.
**Commits:** `46b5a5df`

```diff
+/** The three permanently-locked combat systems, as the score's own term ids.
+ *  Changing this list is a `[needs-user-call]`, not a tuning decision. */
+export const LOCKED_MECHANIC_TERMS = ['conviction', 'surge', 'dice'] as const;

+ *  longer first-class and the score refuses to compute. */
+export const LOCKED_SPINE_WEIGHT_FLOOR = 0.25;

+export interface CombatQualityWeights {

+    /** Decision width — how many live lines at each powering die. */
```

commits** (04c75d22 back through 08745441 — essentially the whole
pivot day) — re-measured with the reduced-nightly pass
(`npm run baseline:regen -- --runs=30 --confidence=reduced-nightly`),
now committed at `f96f0584`.

This is the first regen to run since Phase 43 shipped `combatQuality
Index`, so it's the first *standard* baseline stamp to carry CQI
rather than just win rate: early 0.746, mid 0.739, late 0.814,
impossible 0.820 (spine/arc/width/identity, 0.40/0.25/0.20/0.15).
`statusEngagement` is still reported alongside (0.210 / 0.190 / 0.205
/ 0.218) but per Phase 43's own ruling grades a doctrine that no
longer exists.

**Deliberately not filed as a doctrine-curve violation.** Win rate
this cycle reads early 54.5% / mid 8.3% / late 0% / impossible 0% —
against the old 80/50/25-35/0 curve that would be a fresh, sharp
violation (early down another 4.6pts from 08-08's 59.3%, worth a row
under the old rules). But `46b5a5df` ("Win rate is not a term at all…
a 0%-win cell scoring well is pinned as correct") retired that curve
as a grading concept the same day this loop last measured against it.
Filing a violation row against a law the owner already voided would
be exactly the "loop votes on its own constraints" failure mode the
digest's rails exist to prevent — so this cycle reads CQI instead,
and files a `plan/AUDIT.md` row flagging that `skills/digest.md` §3b
still tells the *next* digest to do the win-rate reading regardless
(see the new `[docs]` row). No CQI band exists yet to grade "moved" or
"violates" against — that's a design ruling for whoever writes the
skill's replacement instruction, not a metric this digest can pick on
its own authority.
