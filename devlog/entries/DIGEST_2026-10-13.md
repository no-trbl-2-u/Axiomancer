# 2026-10-13 — The game starts checking its own rules and numbers

> The automated builder that writes most of this game's code paused for
> about a day to rebuild how its own changes reach the game, then picked
> back up. Once it did, it built three new self-checks, all still waiting
> on the maintainer's review: a tool to measure how hard every early fight

> the three are live yet, so there is nothing new to see in the game

> knowing, and those are below.

## [infra] A one-day pause rebuilds how changes reach the game

**What:** The automated development loop that ships most changes to this
game paused for about a day. When it picked back up, changes no longer
land directly: each one now opens as a reviewable, named change for the
maintainer to approve, with at most three waiting for review at a time.
The pause also lifted a standing restriction that had kept the automation
from authoring new game content on its own.

**Why:** the restriction and the direct-landing process both dated from
the project's "revamp" — the period that rebuilt combat, the world and
the enemy roster from scratch. With that period over, the team decided
new work needed a human checkpoint before it reaches the game, rather
than landing unreviewed. Nothing a player sees changes by itself; it
changes how every future change gets there.

**No capture:** a process change to the development loop itself; no
screen, card or rule changed.

## [infra] A tool built to measure how hard every early fight actually is

**What:** A new measuring tool plays two different card decks — the
plain starting deck and the blood-cost "Blood Price" set — through every
one of the game's 26 Act One fights, at three different character builds
each, and records how often each deck wins and how close to death each
fight brings the player. It isn't switched on yet; that needs the
maintainer's review first, then one manual run to produce the first
reading.

**Why:** since the combat rebuild, there's been no reliable way to say
whether an early fight is too easy or too hard — judgment has rested on
playing it and guessing. An early, unofficial test run already turned up
something worth a look: the Blood Price deck won every single one of its
test fights, while the plain deck's win rate swung from 20% to 95%
depending on the build. That's a finding for the designer to weigh, not
something the tool changed on its own.

**Commits:** `cdba0b85` (on PR #505, awaiting review)

**No capture:** a measurement tool with no run committed yet; it changed
no screen, card or number.

## [infra] A checker built to catch game content nobody can reach

**What:** A new checker reads every enemy, item, relic, character and
quest the game knows about and asks two questions of each: does it point
at something that no longer exists, and can a player actually reach it
through ordinary play? Its first run found zero broken references and
one unreachable piece of content: a ring called the Bleeding Signet,
which exists in the game's data but which nothing currently gives to a
player outside the developer menu.

**Why:** content that nobody can reach has always been invisible by
definition — nothing was watching for it before, so it could sit
unnoticed indefinitely. The Bleeding Signet finding is filed for the
designer to decide whether to grant it somewhere or cut it; it is not
fixed by this change.

**Commits:** `aaaa8571` (on PR #507, awaiting review)

**No capture:** an audit tool; the ring itself is unchanged.

## [infra] The game's first written rulebook for cards, checked by machine

**What:** A draft rulebook now exists for what a card is allowed to do —
how complex a card can be for its rarity, a floor on how simple a
"filler" card must stay, a template for the newer "Global" effect cards,
and a rule for which keywords need a supporting mechanic. Every card in
the game is now checked against it automatically; a future card that
breaks a ratified rule fails that check before it can ship. Running it
against today's cards found 18 existing Blood Price cards already over
their rarity's complexity limit, and five keywords whose rule needs a
decision — both filed for the designer's next card session, not fixed
here.

**Why:** until now, what a card was "allowed" to do lived only in the
designer's head. Writing it down and checking it by machine means a
future card can be caught before it ships, instead of after.

**Commits:** `bd6fe0fc` (on PR #509, awaiting review)

**No capture:** a documentation and lint change; no card's text or
numbers changed.
