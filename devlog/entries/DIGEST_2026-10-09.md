# 2026-10-09 — Desktop screens stop stretching edge to edge

> No new system tonight — this is a catch-up window, closing out a long
> list of small places where the game said one thing on screen while doing
> another. The worst repeat offender, a wide desktop window stretching a
> screen's content edge to edge with huge gaps on either side, got caught
> by three critique passes in a row on three different screens before
> anyone noticed it was the same bug each time; all three are fixed now,
> and the pattern itself is flagged so the next screen doesn't cost
> another pass. The map now calls its own exit door and forge what their
> own screens call them. A fight preview shows later phases actually
> hitting harder instead of repeating one header five times, and stops
> marking an incoming hit with the "+" sign the game otherwise uses for
> gains. Combat's own vocabulary agrees with itself everywhere it prints —
> the good die face, the VULNERABLE effect, the fight summary. A
> screen-reader fix removes a button that was hiding inside another
> button. And a test suite that broke on the 7th got caught and fixed the
> same day.

## [ui] Desktop screens stop stretching edge to edge

**What:** Three screens — the main menu, the fight preview, and the rest
and settlement screens — had their rows and buttons capped to one centred
column on a wide window instead of running the full width with huge gaps
near the edges.

**Why:** Three critique passes in a row (69, 70, 71) each caught the exact
same bug on a different screen: on desktop, a screen's content stretched
the full window width, putting a price or a label hundreds of pixels from
what it described. Catching it screen by screen cost three nights and six
commits; the dispatcher has now flagged the duplication itself as a
candidate for one shared fix instead (see *Tuning proposals*).

**Commits:** `9c435716`/`560de043` (main menu), `31c785d8`/`ece8b5ce`
(combat preview), `9bd8b26c`/`992cf29f` (rest & village)

**No capture:** none of these changed a committed baseline screenshot this
window, so no before/after pair is available; each carries its own layout
test instead.

## [ui] The settlement screen keeps its header and exit bar inside its own frame

**What:** The settlement screen's heading and its exit bar used to sit on
top of the decorative vignette border around the screen rather than inside
it. They now pad in by the same width the border itself uses.

**Why:** the border exists to frame the screen's art; a heading or a
button sitting on top of it instead of inside it reads as unfinished.

**Commits:** `3284b582`

**No capture:** no committed baseline screenshot changed this window.

## [ui] The map names the exit door and the forge what their own screens call them

**What:** A region's exit door used to show "QUEST" with a scroll icon in
the map's node panel; it now reads "PATH ONWARD." The Breakwater's
blacksmith node used to show "BLACKSMITH" in that same panel while the
screen it opens is titled "THE ANVIL" — the panel now says "THE ANVIL"

**Why:** the walkthrough that checked the game right before its first
tagged release (the "RC walk") flagged both: a player reads one name on
the map, then opens a screen with a different name, with no way to know
they're the same place.

**Commits:** `444f5a38`

**No capture:** no committed baseline screenshot changed this window.

## [ui] The fight preview shows a battle actually getting worse, and reads a hit as a hit

**What:** Previewing an upcoming fight used to collapse every phase after
the first into an identical row reading "PHASE 2 · ATTACKS" through
"PHASE 5 · ATTACKS," hiding that later phases hit harder. Each row now
names its own damage. Separately, opening a phase used to repeat that
number as "(+11 damage)" — the same sign the game uses for gains (a +24
buff, +43 healing) — making an incoming hit look like something good
happening to the player. It now reads "11 damage," unsigned.

**Why:** both fixes come from two critique passes in a row (69, then 70)
reading the same screen: a preview that can't show a fight escalating, or
that marks a hit with a "+", fails at the one job a preview has — telling
the player what's about to happen to them.

**Commits:** `c60e4f00`/`ccf6f7eb` (phase headers; the same tick also
fixed a test's import path in `94d3f412`), `f087b6dc`/`544f9422` (the
damage sign)

**No capture:** no committed baseline screenshot changed this window.

## [ui] Combat's own vocabulary and numbers agree with each other, wherever they print

**What:** Four places where the game used two different words or two
different numbers for the same thing, all closed this window: the good
die face is called "BOON" everywhere now (the combat primer used to call
it a "SPECIAL face"); A Plain Word's VULNERABLE effect now prints the same
percentage on the hand, the card detail, the spoils preview and the deck
list (the detail screen was the last holdout, still printing a raw
multiplier like "×25"); the spoils preview under a card offer now shows
the same numbers the hand itself will deal, scaled to the player's current
stats; and the end-of-fight summary spells out "12 plays" instead of an
unexplained "12ph," only prints a DoT damage total when DoT actually dealt
damage, and lists every card that was played.

**Why:** a player who sees the same mechanic described two different ways
in two different places has to guess which one is real. These four are
the last of a batch the pre-release "RC walk" flagged for exactly that
reason.

**Commits:** `b082c21b`/`bcb76681` (BOON), `19459d23`/`59edd577`
(VULNERABLE percent), `e6fc213c`/`01834312` (spoils numbers),
`4e4a2e26`/`72d3bdb1` (fight summary)

**No capture:** no committed baseline screenshot changed this window; the

## [ui] No control sits inside another control anymore

**What:** Two places in combat had one tappable control nested inside
another — the die face inside the staged card, and an item's USE/DISCARD
buttons inside the item card's own expand button. Both are now separate,
sibling controls.

**Why:** a nested button is invalid for both the browser and a screen
reader: a tap can fire both controls at once, and assistive tech has no
correct way to describe "a button inside a button." This was one of the
pre-release walkthrough's findings; two smaller console warnings it also
named (an outdated `element.ref` access, a CSS transform passed to a web
element) are still open.

**Commits:** `46f7f3b8`

**No capture:** no committed baseline screenshot changed this window.

## [infra] A red test suite gets caught and fixed the same day it broke

**What:** the prior digest filed a finding that the project's root test
suite had been failing on `main` since a 2026-10-07 commit — a code
comment describing a UI layout ("phase 1 of 5" as a row) accidentally
matched the pattern a different guard uses to catch comments narrating old
build-plan history. The comment was reworded; the guard's own rule is
untouched, so it still catches what it's meant to catch.

**Why:** this is the kind of gap a per-commit gate can miss (neither
package's own test run touches this root-level check), which is exactly
why the digest runs its own full-repo sweep — and it closed the same day
it was filed.

**Commits:** `6a41768c`/`361d5390`

**No capture:** a comment wording change and a test-import fix touch no
screen.
