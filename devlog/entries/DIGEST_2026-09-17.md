## [infra] Telemetry hook: from losing rows to over-logging to exactly right

**What:** Three PRs in sequence. PR #316 found `TELEMETRY.md`'s hook
writing to a bare relative path — any tick working inside a workspace
package silently diverted its rows into a second log there, losing 7 rows
since 2026-08-12 — plus no completion events (25% of `/march` ticks
logged nothing downstream, indistinguishable from a failure) and 54% of
rows recording the model as `unknown` from a regex that could match a
nested sidechain. Fixed all four, plus dropped a column that had carried
zero information across 410 rows. A same-PR follow-up (`b9308699`)
caught its own new `Stop` hook leaving `tickStart` unset for attended
sessions that never hit a slash command. PR #320 then found the `Stop`
hook over-corrected: it wrote a `tick-end` row for *every* turn, so
ordinary conversation dirtied the log and demanded a commit per turn.
Now a tick only closes with a row if it actually logged something (a
slash dispatch, a skill, a subagent) or still has a call open.

**Why:** the log exists so a human can tell a failed tick from an
invisible one; a hook that loses rows or drowns them in conversational
noise defeats that on either side.
