# 2026-10-07 — The reset reaches its checkpoint, Act One tagged and released

> Six days, not one: a GitHub outage silently cancelled two scheduled
> digests, so tonight catches up all of it. The headline buries the rest —
> the designer walked all four regions in person, then tagged and released
> **v0.1.0-checkpoint**, the point the game returns to if work ever needs to
> pause before new content starts. Getting there took a relic shelf trimmed
> to one survivor, a real level curve, a save fix so a reload mid-fight
> can't skip it, every tutorial window removed, and a full pass making the
> game's own documentation describe only what's actually in the tree. A
> laggy preview build led straight to a 200-megabyte image hiding under the
> map. Since the tag, four small reading bugs found by this week's critique
> and audit passes are already fixed.

## [mechanics] Act One reaches its checkpoint — v0.1.0-checkpoint tagged and released

**What:** The designer personally walked a new game through all four Act 1
regions — the Breakwater, the Charcoal Wood, the Beacon Crags, and the
Lantern Deep — checking every region's door fight, its normal monster, its
rarer elite, a mercy choice, its blacksmith, its healing potions, and the
two now-sealed endpoints (an old vault door and a deep stairway). The walk
proves the four regions work, not that the three starting cards can win
every fight — where they couldn't, the walk used a developer menu to settle
the fight and kept going. Afterward, every tutorial coach and hint screen
in the game was removed outright (they'd been superseded by the simpler
starting kit), and the build was tagged and released as
**v0.1.0-checkpoint**, with an Android preview build attached.

**Why:** The designer's own framing for this release: "get everything to a
good checkpoint with the mechanics in place, the map working, and
everything cleaned up. Then we'll cut a release before we start work on
content, cards, people, story, ... This way, if I want to pump the brakes,
we can reset to this release version." Everything else this window — the
relic trim, the level curve, the save fix, the documentation pass — was
groundwork clearing the way to this point.

**Commits:** `457d9608` (the walk), `859cef19`/`9ddba0f8` (tutorial
removal), `5eb07c48` (the tag and release)

**No capture:** a release tag and a four-region playtest session have no
single screen to pair as a before/after; the nightly catalog tool found no
card, enemy, or affliction text changed this window.

## [content] The relic shelf drops to one survivor

**What:** The ten placeholder relics that stood in since the reset began —
each granting the same flat shield — are gone outright, along with the
shield mechanic itself. The Suppliant's Ring is now the only relic in the
game, and it's the one the player's mercy action runs through.

**Why:** The placeholders existed only to keep old save slots and tests
working while the engine purge finished; once the purge landed, there was
nothing left to make them simpler for, so this window deletes the stand-ins
rather than keep ten relics to rebuild from scratch later.

**Commits:** `37e77313` (phase R7e2)

**No capture:** relics aren't part of the nightly Cards/Enemies/Effects
catalog, and a deletion leaves no "after" picture to pair with a "before."

## [bug] A laggy preview build traced to a 200-megabyte image under the map

**What:** The designer reported the v0.1.0-checkpoint preview build running
laggy on every screen. The cause: the map drew every road and glow on a
region in a single image the size of the whole map, and the phone's
graphics layer turned that into one solid picture — as large as 200
megabytes on a dense display — that stayed loaded for the entire time the
map was open, even behind other screens. Roads now draw as small separate
pieces instead of one giant sheet, cutting that picture down to roughly
12–17 megabytes per region.

**Why:** The fix is checked by calculation and by the browser version of
the game, but nobody has actually played the fixed build on an Android
phone yet — that's the one thing standing between this fix and being
trusted, and it's called out explicitly as unfinished below.

**Commits:** `6e8b4042`

**No capture:** the fix changes nothing on screen, only what's drawn behind
it; the nightly shot tool found no pixel difference to diff.

## [mechanics] A real level curve, and a reload mid-fight can't skip it

**What:** Character levels across Act 1 now climb along a tuned curve built
for the three surviving monsters and four regions, replacing placeholder
numbers. Separately: closing the app in the middle of a fight and reloading
used to silently skip that fight entirely — it now puts the player back
in front of it, offered again from the start.

**Why:** Both were on the short list the checkpoint release couldn't ship
without: a level curve tuned for the game that actually exists, and a save
system that can't let a player lose or skip a fight by force-closing at the
wrong moment.

**Commits:** `61d16fcf` (progression retune), `1bad8fce` (save checkpoint
in fights)

**No capture:** a numeric tuning pass and save-timing logic change no
screen directly.

## [ui] Grey cards get real art, a real name, and a cleared "learn a card" screen

**What:** The three starting cards show actual paintings now instead of a
blank placeholder. The app's own name, as it appears on a phone's home
screen, is "Miserere Mei, Deus." Levelling up no longer offers a card to
learn — with only three cards in the whole game, that screen had nothing
left to offer, so it now gives stat points only.

**Why:** Each is pre-tag cleanup: dead screens and placeholder art that
would have sat, confusingly, inside the "this is the checkpoint" release
otherwise.

**Commits:** `049174f2` (phase R8)

**No capture:** the card art swap is an asset-pool change the nightly
catalog tool doesn't track (it diffs card rules text, not art), and no
baseline screenshot was recaptured this window.

## [infra] The game's own documentation rewritten to describe only what's real

**What:** Five more ticks rewrote the design doctrine, deleted the old
pre-reset archive folder outright, and rewrote comments across both the
game engine and the mobile app so they describe the code as it stands
today — not the mechanics the reset already removed.

**Why:** Any doctrine or comment still describing a deleted mechanic is a
trap for the next person (or the next AI session) reading it — it can look
like instructions to bring the mechanic back. This pass runs right before
the checkpoint specifically so nothing stale survives into the release.

**Commits:** `2a79e596`, `29f3b174`, `6f9a74aa`, `22f4e41f`, `6bbca8a6`

**No capture:** documentation and source comments only; no in-game screen
changed.

## [ui] Four small reading bugs, found and fixed this week

**What:** Since the checkpoint tag, this week's automated playtests and
audit sweeps caught and fixed four small places where the game's UI said
something different from what it actually does: the map's legend — the
only key to what the node colours mean — was unreadable bone-on-terrain
text at 9 pixels, and now sits on its own small plate; a phone-width combat
screen's turn tracker was stacking into a tall column instead of staying a
single row; a card's percent effect was printing a bare number with the %
missing; and the map's "no path chosen" message claimed paths close behind
you, when they actually stay open.

**Why:** None of these are judgment calls — each is a place the interface
was flatly wrong about what the game does, the kind of gap this week's
critique and audit passes exist to catch.

**Commits:** `ddb93536` (map legend), `67fc1541` (combat phase ledger),
`ef0e7a8b` (FREE percent chip), `ae281b4d` (map drawer copy)

**No capture:** none of these changed a committed baseline screenshot this
window, so no before/after is available; each fix carries its own targeted
test instead.

## [bug] The run history now reads events in the right order

**What:** The in-game Chronicle — the one screen that looks back at what
happened recently in a run — was showing its twelve oldest buffered events
first instead of its twelve newest, so a check for "did the player just
change regions" was comparing against stale information.

**Why:** Filed as a bug the day after the checkpoint walk and fixed this
window, so the one place a player can review a run's recent history
actually shows the recent history.

**Commits:** `09161ae7`

**No capture:** no baseline screen changed; the fix is in event-ordering
logic, not layout.
