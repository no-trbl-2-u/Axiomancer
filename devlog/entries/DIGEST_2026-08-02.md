## [mobile] pre-fight encounter preview now matches live combat VITAE

**What:** the pre-fight combat-prelude text now derives displayed enemy
health from the same `withScaledEnemyHp` helper the live encounter uses,
for every enemy — not just the one case a prior fixture happened to
cover.
**Why:** `composeCombatPrelude` read the enemy's unscaled `health`, but
`beginHazardEncounter` applies the `ENCOUNTER_ENEMY_HP_MULTIPLIER` (2x)
testing knob before combat starts, so every preview under-reported the
live VITAE bar by exactly that multiplier (e.g. Little Belle: preview
"50 hp.", live bar "100/100"). CRITIQUE pass 12 finding, issue #162.
```diff
- const health = enemy.health;
+ const health = withScaledEnemyHp(enemy).health;
```
**Commits:** 15d45699 (issue #162 — see the `[infra]` card below for why
this needed a hand-close)

## [mechanics] draft scorer guarantees newcomer/sandbox card visibility

**What:** `draftCombatDeck` now forces every distinct `extraCards`
newcomer id into the draft when the stage/tier pool allows it, per-id
rather than per-class (a set can carry multiple newcomers and a generic
"some newcomer present" check let one hide another).
**Why:** the policy-pick draft scorer's weighted-random pick left
`extraCards` newcomers as low-weight, tail-position candidates in a
70-90 card pool — `ingot-of-ruin` drew 0/24 times across 3 canonical
late-stage seeds despite being structurally draftable, and matrix-level
stage deltas in sandbox A/Bs were consequently a pool-shuffle artifact,
not a card signal. CRITIQUE HIGH finding, issue #163 — resolved the
tuning-harness AUDIT row of the same name.
```diff
+function guaranteeNewcomers(pool, extraCardIds, stage) {
+    for (const id of extraCardIds) {
+        if (!alreadyDrafted(id) && poolAllows(id, stage)) forceInclude(id);
+    }
+}
```
**Commits:** fbace426 (issue #163, closed cleanly this time — see below)
