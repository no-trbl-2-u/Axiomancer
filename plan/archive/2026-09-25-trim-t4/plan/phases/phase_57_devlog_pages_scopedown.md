>

> Infra/CI phase, not a page-family/feature-surface phase. Several

## Outcome

`https://axiomancer.pages.dev/devlog/log.html` (and `/index.html`,
`/catalog.html`, every `entries/*.html`, `/tuning-lab/index.html`) stop
being reachable, because the generated HTML that Cloudflare Pages
serves from `main`'s tree is no longer committed to `main`. The DevLog
stays reachable to the humans who use it via `npm run site:build`
locally (unchanged command) — it is a local-build artifact now, not a
published one. A guard rejects any future commit that re-introduces
the generated files into the tracked tree, so this can't silently
regress the way the 2026-08-10 ruling did in the five days before this
phase was queued.

## Why (context, not to re-litigate)

`plan/AUDIT.md`'s divergence row (impact 8, confirmed live 2026-08-12,
queued to this phase 2026-08-15) found `build-devlog.yml` committing
generated DevLog HTML to `main` "so the existing Cloudflare Pages
integration can serve them" — and that HTML's own page header reads "A
private index of the game's content and the nightly development log."
T's ruling: scope it down. The Cloudflare project itself (production
domain + guessable per-branch previews) needs a human at the dashboard
and stays out of scope here; this phase drains only the in-repo half —
which is also the half that actually contains the private content.

## Root-cause scope (read before touching workflow YAML)

Committing generated DevLog HTML to `main` happens in **two** places,
not one — the AUDIT row named only `build-devlog.yml`, but
`skills/digest.md` §3 step 4 does the same thing every night
("Commit the entry, the built HTML, `devlog/data/**`, and any
`devlog/assets/**` together"). Fixing only the on-demand workflow
would leave the nightly `/digest` commit re-introducing the exposure
the very next night. Both call sites are in scope.

## Generated vs. source — the split this phase turns into policy

Every file under `devlog/` was being committed identically. They are
not identical:

**Generated (derived from other tracked sources; safe to gitignore,
rebuilt on demand by `npm run site:build`, no data loss):**
- `devlog/index.html`, `devlog/log.html`, `devlog/catalog.html`
- `devlog/entries/*.html` (one per `.md` source)
- `devlog/tuning-lab/index.html` (the generated list page — NOT the
  hand-authored reports it lists)
- `devlog/data/*.json` (`cards.json`, `effects.json`, `enemies.json`,
  `meta.json` — regenerated by `npm run catalog:export`; `axio-mcp-server.mjs`
  already self-heals on missing/stale copies, confirming these were
  always meant to be regenerable, not archival)
- `devlog/assets/catalog/**` (70 files — card/enemy art copied by
  `catalog:export`, same regeneration path as the JSON above)

**Source (irreplaceable inputs; stay tracked, unaffected by this
phase):**
- `devlog/entries/*.md` — the `/digest`-authored ledger; the one thing
  nothing else can regenerate.
- `devlog/assets/<date>/*.png` (dated dirs, e.g. `2026-08-11/`,
  `2026-07-04/`) — `devlog:shots` screenshot captures of a specific
  day's before/after; not derivable from anything else committed.
- `devlog/tuning-lab/tuning-lab-*.html` — hand-authored tuning
  reports (the *list* of them is generated; the reports themselves are
  not).
- `devlog/README.md` — docs.

## Decisions made upfront — DO NOT ASK

1. **Artifact shape: local build, not CI artifact download.** The
   brief's own text offers "artifact-only, or an unserved path."
   `build-devlog.yml`'s existing "Upload DevLog site" step already
   satisfies "artifact-only" (14-day-retention `actions/upload-artifact`),
   so no new plumbing is needed there. But the *primary* human-reachable
   path stays `npm run site:build` run locally — same command
   contributors already run, output opens straight from the
   filesystem, no Actions-run hunting, no 14-day expiry. Both remain
   true after this phase; neither needs new code.
2. **Untrack, don't relocate.** The brief offers "an unserved path" as
   an alternative to artifact-only. Rejected: Cloudflare Pages' output
   directory is configured outside this repo (confirmed — no
   `wrangler.toml`/`_headers`/Pages build-config file exists anywhere
   in-tree), so there is no in-repo path this repo can prove is
   unserved. `.gitignore` + untracking is the only in-repo lever that
   actually removes content from what Pages can serve, because Pages
   serves what `main`'s tree contains.
3. **Remove the *currently tracked* generated files now, not just stop
   future commits.** The live exposure is the 181 files already on
   `main` today. Changing the workflow/skill going forward without
   `git rm --cached` today's copies would leave
   `axiomancer.pages.dev/devlog/log.html` live and unauthenticated
   until the next `/digest` run happens to overwrite it — which could
   be another five days, exactly the failure mode that got this row
   escalated impact 6→8 in the first place.
4. **The guard is a script + two call sites, mirroring the
   `check-lexicon.mjs` precedent** (same shape: zero-dep Node script,
   local pre-commit hook for the fast path, a scheduled/dispatchable
   CI workflow as the remote backstop). New script:
   `scripts/check-devlog-not-served.mjs`. It runs `git ls-files
   devlog/` and fails (exit 1) if any path matches the "Generated"
   list above. Wired into:
   - `.githooks/pre-commit`, gated on staged paths touching `devlog/`
     (same pattern as the existing lexicon gate in that file).
   - New `.github/workflows/check-devlog-served.yml`, scheduled
     weekly + `workflow_dispatch`, mirroring `check-lexicon.yml`'s
     structure exactly (same cron day, offset by a few minutes to
     avoid runner contention — `31 7 * * 0`).
5. **`build-devlog.yml`'s "Commit generated changes" step is deleted,
   not modified to filter paths.** Once the generated paths are
   gitignored, `git add devlog/` in that step stages nothing (git
   respects `.gitignore` on `add` unless `-f`), so the step becomes a
   guaranteed no-op — dead code reads as intent that no longer exists.
   Delete it; keep the validate + upload-artifact steps (still
   correct: the artifact upload doesn't care about tracking status).
6. **`skills/digest.md` §3 step 4's commit line changes from "the
   entry, the built HTML, `devlog/data/**`, and any `devlog/assets/**`"
   to "the entry, and any new `devlog/assets/<date>/**` screenshots
   from step 4a."** The built HTML and `devlog/data/**` are dropped
   because they're gitignored now; `devlog/assets/catalog/**` (also
   gitignored) was never a digest-night output anyway (only
   `catalog:export` touches it). The dated screenshot subdirs
   (`devlog/assets/<date>/**`) stay explicitly named since they're the
   one `assets/**` subtree still worth an explicit call-out (source,
   not generated).
7. **`devlog/README.md` gets one paragraph corrected**, not a rewrite.
   Its current "Everything served here ... is committed; no build runs
   on the host" sentence becomes false the moment this phase ships;
   leaving it would mislead the next person who opens the file to
   understand the DevLog. Scope the edit to that one paragraph.
