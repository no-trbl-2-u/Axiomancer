## Output schema / contracts

`TooltipKind` union gains one member: `'hazard-keyword'`.
`TooltipContent` shape unchanged (`{ title, body, footnote?, accent?
}`) — hazard keywords have no natural footnote and use `accent:
'neutral'` (no stat tie, matching `stance-chip` / `disabled-action`).

## Empty / loading / error states

- **No keywords in deck:** unchanged — the existing `vm.keywordTally.length
  > 0` guard already hides the whole section; no new empty state
  needed.
- **Unknown keyword id** (defensive; `HazardKeywordId` is a closed
  union so this can't happen from `vm.keywordTally` in practice):
  `selectTooltipContentFor` returns `null`, `TooltipTarget`'s `show()`
  still fires but `TooltipProvider` renders nothing for a null lookup
  (existing defensive contract, shared by every other kind).

## Decisions made upfront — DO NOT ASK

- **Read `HAZARD_KEYWORDS` directly rather than authoring a parallel
  mobile-side content table.** Every other engine-sourced tooltip kind
  (`effect`, `card`) does the same — the mechanics package is the
  truth source, mobile presenters format/lookup only.
- **`accent: 'neutral'`.** Hazard keywords aren't tied to a
  heart/body/mind stat the way combat effects are; `stance-chip` and
  `disabled-action` set the precedent for neutral-accented non-stat
  tooltips.
- **No footnote.** `HAZARD_KEYWORDS` entries carry only `name` +
  `desc`; inventing a footnote would be uncited flavor, not data.
- **`testID` unchanged** (`hazard-deck-kw-${row.id}`) — preserves the
  existing screen test's ability to assert chip presence by id; new
  tap-to-open-tooltip coverage is additive, not a rename.
- **Style prop on `TooltipTarget`, not an inner wrapper `View`.** The
  chip's `kwChip` style (row layout, border, padding) moves onto the
  `Pressable` itself, matching the documented `TooltipTarget.style`
  contract for flex children (see the component's own JSDoc).

## Mobile reflow / responsive

No layout change — `TooltipTarget` renders a `Pressable` in place of
the `View` it replaces, same style object, same flex-wrap parent
(`styles.kwWrap`).
