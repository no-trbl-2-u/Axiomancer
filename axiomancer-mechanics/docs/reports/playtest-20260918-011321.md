## Fix applied this tick — capitulation offers now honor each witness's own strategy

Handoff #1 below (originally filed as a "recommend a dedicated
follow-up, don't ship blind" finding) has been shipped in this PR at
the user's explicit direction. What shipped:

- `src/Combat/combat.sim-policies.ts` — added `capitulationChoice:
  'accept' | 'continue'` to `CombatSimPolicy` (mirrors the existing
  `mercyChoice` seam). Only `mercy-seeker` (mercy is its whole
  identity) and `chaos` (the non-optimizing noise floor) `accept`;
  every other witness (`greedy`, `blind`, `dot-weaver`,
  `control-lock`, `aggro-brute`, `turtle`) now `continue`s — plays
  through the offer toward its own preferred win condition, per
  CLAUDE.md's "alt-wins compete on merit, none is protected."
- `src/Combat/combat.encounter.sim.ts` — both capitulation call sites
  now resolve `selectCapitulationChoice(state, policyObj.capitulationChoice)`
  instead of a hardcoded `'accept'`, and only `break` the sim loop on
  `accept`; `continue` resumes `phase-play` (no infinite-loop risk —
  `capitulationDeclined` gates the offer from reopening in the same
  fight, per `combat.engine.ts:1579`).
- `src/CLI/combat.cli.ts` (`resolveCliCapitulationChoice`) — `--auto`
  now declines (`continue`) instead of unconditionally accepting;
  none of the CLI's four auto-policies (`status`/`aggressive`/
  `safe`/`naive`) is a mercy-seeker analog, so none should reflexively
  take the first yield offered.
- Verified: full package typecheck clean; all 83 e2e test files / 1213
  tests in `src/Combat/e2e/` + `src/CLI/e2e/` pass unchanged (including
  the matrix-determinism and balance-bands smoke tests — the sim is
  still fully deterministic per seed, it now just plays out differently).

fix; numbers below in the rest of this report are the corrected

### Mid stage (The Long Road)

Deck: `draft:damage` (deliberately opposite of greedy/blind's status-
first lean), policy `aggressive`, + 2 contrast fights (`draft:control`,
`draft:utility`). 7 seeded fights (tri-eyes, mirac x3, jeweled-tree,
hasshaku-sama; seeds 101–707).

| enemy | seed | deck | outcome | notable |
|---|---|---|---|---|
| tri-eyes | 101 | damage | Victory (HP) | one card looped its die 3x for an exact 150/150 kill |
| mirac | 202 | damage | Victory (HP) | closed via Communion of the Worm (150 DoT) + direct hits |
| mirac | 303 | damage | **Defeat** | genuine near-miss, enemy left at 2/330 HP |
| jeweled-tree | 404 | damage | Victory (HP) | single card (154) carried it, player barely scratched |
| hasshaku-sama | 505 | damage | Victory (HP) | player took only 4 damage total |
| mirac | 606 | control | Defeat | 0 DoT dealt, no mercy path opened either |
| mirac | 707 | utility (befriend-weighted) | Victory (HP) | mercy modal never opened |

**Root cause found:** `draft:utility`'s 4x weight toward the
`'befriend'` verb class points at an empty bucket — grepping the full
card library found **zero cards carrying the `befriend_attempt`
mechanic**. Confirmed independently by the impossible-stage agent
too (128-card production library, 0 matches; only present in test
fixtures).

**Verdict (confidence 78):** direct-HP victory is the *default*
outcome with a damage-postured deck (4/5 clean kills, including
against mirac and jeweled-tree — the two enemies the matrix showed
0/60 direct wins for). The matrix's near-100%-mercy read for
greedy/blind is a **policy artifact**: those sims are documented in
`combat.sim-policies.ts` as status/sway-first play, and the mercy
route they take is capitulation (Sway crossing
`capitulateThreshold(enemy)`), not literal Befriend. Friction: the
top-level "Phases: N" count doesn't match the per-card attribution's
"over N phases" (combat phases vs. per-card die-loop iterations —
different countings, no `--json-events` needed to notice the
mismatch but needed to explain it); several off-focus cards read as
dead weight in a fast aggressive deck.

### Late stage (The Deep Wood)

Decks: `draft:dot`/`naive` and `draft:control`/`safe`. 9 seeded fights
across the full 6-enemy roster (seeds 101–303).

| enemy | seed | deck | outcome | notable |
|---|---|---|---|---|
| fire-giant | 101 | dot | Victory (HP) | clean kill, no PLEA offer fired |
| rangda | 101 | dot | Victory (HP) | clean kill |
| tezcatlipoca | 101 | dot | Victory (HP) | clean kill |
| death | 101 | dot | Victory (HP) | clean kill, 625 DoT / 385 direct |
| arch-demon | 303 | dot | Relented | enemy at 14% HP when auto-accepted |
| fire-giant | 202 | control | Relented | enemy at 9% HP when auto-accepted |
| arch-demon | 202 | control | **Defeat** | genuine attrition loss, 0 DoT |
| the-abortive | 202 | control | **Defeat** | enemy still 45% HP — clean HP loss |
| rangda | 303 | control | Relented | enemy at 2.5% HP when auto-accepted |

**Root cause confirmed in source, independently verified by me:**

```
src/Combat/combat.encounter.sim.ts:781,799
    state = selectCapitulationChoice(state, 'accept').state;

src/CLI/combat.cli.ts:460-462
    const choice: 'accept' | 'continue' = auto
        ? 'accept'
        : (await prompt<...>(...)).choice;
```

Both the pure-sim playtest matrix and the CLI's `--auto` mode
**unconditionally accept** the capitulation/PLEA offer the instant
Sway crosses the enemy's resolve threshold — there is no sim-policy
variant that ever answers `continue`, even when the enemy sits at
single-digit-percent HP and a kill is one good turn away. In
non-auto/interactive play the CLI genuinely prompts accept-vs-
continue (`combat.cli.ts:462-467`), so a real player keeps a choice
every automated harness (sim matrix and `--auto` CLI alike) throws
away. `combat.deck-draft.ts` also guarantees at least one PLEA-
applying card in every drafted deck regardless of focus, which is why
even the "dot" arch-demon run (seed 303) got pulled into a mercy
ending mid-kill.

**Verdict (confidence 75):** direct-HP victory is reachable and was
the *DoT deck's default outcome* (4/5 clean kills, zero help); the
control deck's two defeats confirm HP-loss is an equally real,
un-softened failure state. **The quant matrix's "mercy dominates"
signature is a harness measurement bug, not a balance or design
signal** — three of nine qualitative runs took a mercy exit with the
enemy at 2.5–14% HP, states a `continue`-capable policy would very
likely have converted to a kill. Friction: PLEA/control cards that
decide a fight show "0 dmg (0 DoT)" in the summary — visually
identical to a card that did nothing; cards burned by IMMOLATE are
invisible outside `--json-events`; default text mode gives almost no
detail mid-fight (bare `[event] hazardCombat:card` lines), so a
Relented ending reads as sudden rather than earned unless you reach
for the JSON transcript.

### Impossible stage (The Unprovable — ceiling probe)

Decks: `draft:control` x2, `draft:damage`, `draft:utility`,
`draft:dot`, and a hand-built pure-choir/PLEA deck (`cards:...`) built
specifically to probe the matrix's rare mercy wins. 6 seeded fights,
all against the-incompleteness (seeds 101–606).

| seed | deck | outcome | notable |
|---|---|---|---|
| 101 | control | Defeat | enemy 64% HP left |
| 202 | damage | Defeat | enemy 31% HP left — the best dent of any run |
| 303 | utility (befriend-weighted) | Defeat | enemy at full HP — turtling is the wrong read here |
| 404 | dot | Defeat | fastest death; DoT ramp too slow vs. escalating threat |
| 505 | control | Defeat | longest drafted run (7 rounds), only 6% HP dealt |
| 606 | hand-built choir/PLEA | Defeat | **Sway reached 526/~774 (68%) by round 10** — closest crack found |

**Losing-well finding:** every defeat is attributable to a specific,
named, individually-logged mechanism — escalating threat cards with
damage baked into their own flavor text (177→221→277→277→356 across
rounds), HP-threshold stage transitions that grant new keywords and
heal the enemy, REGROW ticks. It is thematically coherent that
hurting it makes it worse, and that's telegraphed in-fight, not
hidden — a genuinely satisfying answer to "why can't I win," though
only visible via `--json-events`/`--state-log`; the terse default
output doesn't surface it.

**Mercy-crack finding:** the matrix's rare `mercy-seeker` wins here
(2/60) are **not** the Befriend mechanic — confirmed dead content (0
cards, see Mid stage) — but the same generic Sway/RELENT capitulation
system every enemy is subject to, gated at `0.35 x enemy.maxHealth`
Sway (~774 for this boss) with per-round decay if not fed. Reaching
68% of that threshold on a deliberately-built choir deck, and still
dying, reads as a genuine, well-telegraphed, hard-won strategic
outlier — correctly rare, not an oversight.

**A separate, currently-inert bug found and independently verified by
me:** `the-incompleteness`'s own source comment says *"mercy is not
an out"* (no `befriendabilityConfig`), but
`isBefriendAttemptEligible` → `befriendabilityPredicatesPass`
(`src/Combat/index.ts:111-140`) treats a *missing* config as
unconditionally eligible:

```ts
const config = state.enemy.befriendabilityConfig;
if (!config || config.defaultFallback === 'both-defend-cap') {
    return options.requirePassiveCounter
        ? state.friendshipCounter >= FRIENDSHIP_COUNTER_MAX
        : true;
}
```

This is almost certainly the correct default for ordinary enemies
that never bothered authoring a config (most enemies should still be
attemptable) — the bug is that there is no way to author an explicit
*"never eligible"* config for a boss that wants to opt out, so the
missing-config default silently wins for the-incompleteness too. It
is inert today only because no shipped card carries
`befriend_attempt` (see Mid stage); if one is ever added without also
giving this boss an explicit ineligible config, it becomes live and
contradicts the boss's own design intent. Not shipped as a fix this
tick — it needs a real "not eligible" state added to
`BefriendabilityConfig`, which is design/schema work, not a safe
one-line patch.

## Doctrine verdict

Reframed per the Top-line callout (the old status-dominance/CQI/
win-rate-curve question is repealed law): **does each stage's deck
run its own engine, and is the outcome legible?**

- **Engine runs in the hands: yes, at every stage.** Escalating
  poison/bleed, IMMOLATE big-turn payoffs, a hard-won choir/Sway race
  at the ceiling — every qualitative session reported more than one
  live line and more than one card that mattered.
- **Legibility: good for headline HP outcomes, degraded for
  everything else.** Victory/Defeat by HP is clear at every stage.
  Mercy/RELENT, PLEA/control cards' real contribution, die-color
  fizzles, and IMMOLATE-burned cards are all invisible in the default
  (non-`--json-events`, non-debug) CLI output — a real player using
  only plain output would misread several of these sessions.
- **The matrix's own headline number (win rate, V/M/D/R split) was
  unreliable for greedy/blind from mid stage onward** because of the
  capitulation auto-accept bug — the single most important finding of
  the tick. **Fixed in this PR** (see "Fix applied this tick" above);
  every past reading of "mercy dominates past early stage" from this
  harness predates the fix and should be treated as superseded, not
  as current evidence.
