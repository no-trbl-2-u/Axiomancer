# Phase 72 — Run-loop semantics (`resetRun` + `runId` + starting-hearth)

> Closes GH#65 ask 2 (score 4.5). Mobile BEGIN AGAIN currently
> full-heals the player and dismisses the aftermath modal — a
> band-aid because the engine has no run-reset primitive. This
> phase ships the primitive so mobile can model death / restart /
> hearth re-entry cleanly.

## Outcome

`createGameStore` gains a `resetRun({ keepCharacter: boolean })`
method. `keepCharacter: true` preserves the persistent character
ledger (player + philosophicalAlignment + moralMeter +
rngState) and resets run-scoped state (world / combat / quests /
flags / observer cache); the character's HP refills to maxHealth.
`keepCharacter: false` performs a full new-game reset. Every reset
generates a fresh `runId: string` (16-char hex per Phase 35's
character-id pattern), which surfaces on GameState + persists in
the save adapter for future runs-history work. GameState shape
bumps `version` 5 → 6 with `migrateV5toV6` defaulting `runId` for
legacy saves. A hermetic e2e at
`src/Game/e2e/run-loop.engine.test.ts` drives all the preserve /
reset / migration paths.

```typescript
// src/Game/run-loop.ts
import type { MapName } from '../World/map.library';

/**
 * Phase 72 — canonical starting region for `resetRun`. The reset
 * sends the player back to `getMapDefinition('coastal-continent',
 * STARTING_REGION).startingNode.id` (the fishing-village starting
 * node). Per D5 the engine reuses the existing
 * `MapDefinition.startingNode` shape; no new "hearth" primitive
 * needed. Per-region custom hearths defer to a follow-up if
 * regions other than fishing-village ever become start points.
 */
export const STARTING_REGION: MapName = 'fishing-village';

/**
 * Phase 72 — 16-char hex UUID-shaped string from the supplied RNG.
 * Mirrors the Phase 35 `createCharacter` id-generation pattern;
 * deterministic when the RNG is seeded.
 */
export function generateRunId(rng: () => number): string {
    return Array.from({ length: 16 }, () =>
        Math.floor(rng() * 16).toString(16)
    ).join('');
}
```

```typescript
// src/Game/game.reducer.ts — RESET_RUN case sketch
case 'RESET_RUN': {
    const { keepCharacter } = action.payload;
    const freshRunId = generateRunId(getRng().raw);

    if (!keepCharacter) {
        // Full new-game reset; only carry rngState forward.
        const fresh = createNewGameState();
        return { ...fresh, runId: freshRunId, rngState: state.rngState };
    }

    // Preserve persistent ledger; reset run-scoped state.
    return {
        version: GAME_STATE_VERSION,
        runId: freshRunId,
        player: {
            ...state.player,
            health: state.player.maxHealth,
            effects: [], // defensive — already empty between combats
        },
        world: createStartingWorld(),
        combat: null,
        quests: emptyQuestLog(),
        flags: [],
        moralMeter: state.moralMeter,
        rngState: state.rngState,
        philosophicalAlignment: state.philosophicalAlignment,
        // lastSeenAlignmentCells intentionally dropped (observer
        // cache resets — fresh run, fresh observation history).
    };
}
```

```typescript
// src/Game/game.migrate.ts — migrateV5toV6 sketch
interface GameStateV5 extends Omit<GameState, 'runId'> {}

function migrateV5toV6(v5: GameStateV5): GameState {
    return {
        ...v5,
        version: 6,
        runId: generateRunId(getRng().raw),
    };
}
```

Decision **D7** — `runId` is required (not `runId?`); migration
defaults it for legacy saves. Required-field is the right shape so
consumers always have a non-null `runId` to read.

**Files touched:**

**Cases:**
1. `createNewGameState()` returns a non-empty `runId` matching
   `/^[0-9a-f]{16}$/`.
2. `store.resetRun({ keepCharacter: true })` preserves
   `state.player` identity (id, name, level, baseStats, equipment,
   knownSkills, inventory) but refills `health` to `maxHealth`.
3. `keepCharacter: true` preserves `philosophicalAlignment` +
   `moralMeter` exactly (character ledger per D1).
4. `keepCharacter: true` resets `world` (currentMap back to
   fishing-village starting node), `combat = null`,
   `quests = emptyQuestLog()`, `flags = []`,
   `lastSeenAlignmentCells` undefined.
5. `keepCharacter: true` generates a NEW `runId` (string
   inequality vs pre-reset).
6. `keepCharacter: false` resets EVERYTHING to new-game baseline
   (level 1, default alignment, moralMeter 0, fresh player id).
7. Mid-combat reset: `startCombat` → `resetRun` clears `combat`
   and `currentEncounter`.
8. Migration: a v5 save (no `runId`) loaded through `migrate()`
   gets a non-empty `runId` matching the hex pattern; other fields
   pass through unchanged.

        const store = createGameStore(nullAdapter);

        // damage the player

## Decisions made upfront — DO NOT ASK

- **D1 — `keepCharacter: true` preserves the character ledger.**
  Preserved: `player` (entire Character — id, name, level,
  experience, baseStats, derivedStats, equipment, inventory,
  knownSkills, equippedSkills, availableStatPoints, procUnlocks),
  `philosophicalAlignment`, `moralMeter`, `rngState`. Reset:
  `world` (back to `createStartingWorld()`), `combat`,
  `currentEncounter`, `quests`, `flags`, `lastSeenAlignmentCells`.
  HP refills (`player.health = player.maxHealth`); `player.effects`
  clears defensively. Rationale: roguelike "begin again at the
  hearth" — character grows across runs; world / narrative resets.

- **D2 — `keepCharacter: false` is equivalent to a brand-new
  game.** Calls `createNewGameState()` internally; the only thing
  carried forward is `rngState` (don't reset the RNG mid-session —
  that breaks the deterministic-replay guarantee). A fresh `runId`
  is assigned.

- **D3 — `runId` is a required string field on GameState, not
  optional.** Required-field shape ensures consumers always have a
  non-null id to read. Migration (D7) defaults it for legacy
  saves so the required-shape doesn't break load semantics.

- **D4 — `rngState` carries across `resetRun` calls.** The RNG is
  a session-level facility; per-run determinism is keyed off
  `runId`, not by resetting the seed. Consumers that want a fresh
  seed per run can reseed at `resetRun` time; the engine doesn't
  force it.

- **D5 — Reuse `MapDefinition.startingNode` for the hearth.** No
  new "hearth" type primitive — every map already has a
  `startingNode` (the canonical entry point used by
  `createMapState`). `STARTING_REGION` constant names the canonical
  starting region (fishing-village today); `resetRun` calls
  `createStartingWorld()` which already routes there. Per-region
  custom hearths defer to a follow-up — today only fishing-village
  is the canonical start point.

- **D6 — Bump `GAME_STATE_VERSION` 5 → 6.** Adding a required
  `runId: string` is a shape change; the existing migration
  scaffold (`migrateV4toV5` etc.) is the canonical pattern.
  Additive-optional-without-bump (Phase 60/62/68/69 pattern) was
  considered but rejected because `runId` should never be `null`
  at the consumer boundary — required-field is the right contract.

- **D7 — `migrateV5toV6` defaults `runId` via
  `generateRunId(getRng().raw)`.** Legacy saves get a fresh id at
  load time; the id is non-empty + hex-shaped + collision-free in
  the limit (16 hex chars = 64 bits of entropy). Same pattern as
  Phase 35's character id generation.

- **D8 — `generateRunId` ships on the public surface; takes a
  `() => number` rng parameter.** Consumers can call it with their
  own rng for testing / deterministic runs. The engine
  internally always passes `getRng().raw` (the same source used
  by Phase 35).

- **D9 — `STARTING_REGION` ships as a constant export, not a
  configurable.** Today the canonical start region is
  fishing-village; if other regions become start points, the
  engine can either re-set the constant or evolve into a registry.
  Avoid premature configurability per the "Don't design for
  hypothetical future requirements" CLAUDE.md guidance.

- **D10 — `resetRun` is BOTH a store method AND a dispatchable
  action.** The store method (`store.resetRun({ keepCharacter })`)
  is the consumer-facing entry point; internally it dispatches
  `{ type: 'RESET_RUN', payload: { keepCharacter } }` so the action
  flows through the standard `gameReducer` → `set` → `emit` →
  autosave pipeline. RESET_RUN goes into `DURABLE_ACTIONS` so the
  save persists immediately.

- **D11 — Save adapter `runId` persistence.** Both
  `adapter.save()` call sites in `store.ts` (the `dispatch`
  DURABLE_ACTIONS branch + `updateCombat`) include `runId` in
  their destructure + save call. Save format gains `runId` as a
  required field per D3 + D6.

- **D12 — `lastSeenAlignmentCells` resets on
  `keepCharacter: true`.** The Phase 63 observer cache tracks
  per-tree alignment-cell observations; a new run is a fresh
  observation context (the player presumably hasn't seen any NPC
  in this run). Clearing the cache means reactive NPC choices
  hide until the player has spoken to the NPC again in the new
  run — semantically correct for a "begin again" reset.

- **D13 — `moralMeter` preserved per D1 (character ledger), but
  this is a design call that could go either way.** Argument for
  preservation: moralMeter reflects player choices (compassion ↔
  ruthlessness); choices should stick across runs in a
  metaprogression sense. Argument for reset: moralMeter is
  narrative-only per Spec 10 Q4, and narrative resets on a
  begin-again. Brief picks **preserve** to match the
  philosophicalAlignment treatment (both are player ledgers) and
  because the only meaningful reset target is "do I want to start
  over morally too?" — which is what `keepCharacter: false` is
  for. Future content can revisit this if it surfaces design
  friction.

- **D14 — Three commits.** Unit 1 (types + reducer + migration +
  action + store method + run-loop.ts + barrels + fixture) ships
  as one logical commit since the parts are tightly coupled; Unit
  2 (e2e) ships separately; Unit 3 (docs + bearings + README +
  CHANGELOG) ships separately. Plan-row flip is the 4th commit.

- **D15 — No mobile callsite update in this phase.** Mobile-repo
  concern. Brief notes the callsite for the consumer-side cleanup
  (mobile `state/combat-mode.tsx` BEGIN AGAIN dispatches
  `resetRun({ keepCharacter: true })` instead of the full-heal
  band-aid), but the engine ships the surface only.

  true })` could clear the seed. Not needed today.

  Codex / runs-log / per-run XP analytics feature has a key to
  build off. Out of scope here.
