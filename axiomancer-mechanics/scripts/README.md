# scripts/ — verify-gate enforcement + release-engineering tooling

> Sibling to [`automation/`](../automation/) — `automation/` holds
> non-hermetic CLI walkthroughs + dev-facing test reporters;
> `scripts/` holds the **enforcement layer** (deploy-gate assertions,
> public-surface contract, autonomous-loop issue mirror). Nothing in
> here ships in the published npm package (`package.json` `files`
> covers `dist/` only).

## Tools

| Entry point | npm-script wrapper | What it does |
|---|---|---|
| [`deploy-check.mjs`](./deploy-check.mjs) | `npm run deploy:check` | The deploy gate. Runs four structural assertions before `npm pack --dry-run`: (1) `dist/` exists; (2) every `src/<Module>/types.ts` has a matching `dist/<Module>/types.d.ts` (Phase 50); (3) the latest git tag matches the top tagged `## [X.Y.Z]` heading in `CHANGELOG.md`, skipping `(unreleased)` (Phase 52); (4) the current `dist/index.d.ts` snapshot matches `scripts/public-surface.expected.json` (Phase 53). Pre-commit-via-`/march` callers depend on this exit-0 to clear the bump-and-publish flow. |
| [`snapshot-public-surface.mjs`](./snapshot-public-surface.mjs) | — (direct invocation: `node scripts/snapshot-public-surface.mjs [--write]`) | Walks `dist/index.d.ts`, parses every `export { ... } from '...'` + `export type { ... } from '...'` line, emits a deterministic-sorted `{ values: string[], types: string[] }` JSON. CLI mode prints to stdout; `--write` overwrites the fixture. Library mode (`import { snapshotPublicSurface } from './snapshot-public-surface.mjs'`) is consumed by `deploy-check.mjs`. |
| [`diff-public-surface.mjs`](./diff-public-surface.mjs) | — (direct invocation: `node scripts/diff-public-surface.mjs <ref-A> <ref-B>`) | Pretty-prints markdown-shaped Added / Removed / Changed-kind between the public-surface fixture at two git refs. Defaults to `HEAD~1 HEAD`. Output ready to paste into a CHANGELOG entry's bullets per `RELEASING.md`. Both refs must contain the fixture (Phase 53 introduced it, so refs older than that commit won't resolve). |
| [`changelog-additions.mjs`](./changelog-additions.mjs) | — (direct invocation: `node scripts/changelog-additions.mjs <ref-A> <ref-B> [--dry-run]`) | Consumes `diff-public-surface.mjs` output and generates Keep-a-Changelog formatted entries for the `[unreleased]` section in `CHANGELOG.md`. Merges with existing manual entries. Supports `--dry-run` for preview. Eliminates manual CHANGELOG maintenance for public surface changes. |
| [`loop-issue.mjs`](./loop-issue.mjs) | invoked by `/iterate` + `/ship-a-phase` via the autonomous loop | Best-effort GitHub-issue mirror for autonomous-loop work. Opens issues for findings + phases, closes them on the matching ship commit. Requires `GH_TOKEN`. Failure is non-fatal — the loop continues if `gh` isn't installed or the token is missing. |

## Fixture: `scripts/public-surface.expected.json`

The committed contract enforced by `deploy-check.mjs` (Phase 53 unit
2). Hand-edits are NOT the workflow — the file is regenerated by
`node scripts/snapshot-public-surface.mjs --write` whenever the
public barrel intentionally changes. The commit that refreshes the
fixture IS the gesture for "I'm changing the public barrel"; deploy
gate fails on any PR that adds/removes/renames a top-level export
without refreshing the fixture.

Current shape (HEAD, post-Phase-76): **237 runtime exports + 167
type exports** across the 13 module sections. Per-tag history of
additive public-API surface (deriveable via `node
scripts/diff-public-surface.mjs <ref-A> <ref-B>`):

- `v0.10.0`: baseline (post-loop-era first publish).
- `v0.10.1` + `v0.10.2`: no new public surface vs `v0.10.0`.
- `v0.10.3` (post-Phase-60 + Phase 66): added one type at Phase 60
  (`FriendshipReward`, 158 → 159), added two more at Phase 66
  (`SkillSynergy` + `SynergyPredicate`, 159 → 161). Tag shipped at
  233 + 161.
- `v0.11.0` (post-Phase-68 / 71 / 72 / 73): Phase 68 added
  `BefriendabilityConfig` (161 → 162); Phase 71 added three aftermath
  prose types (`FinalBlowLines`, `PactLines`, `CauseLines`,
  162 → 165); Phase 72 added two run-loop runtime exports
  (`generateRunId`, `STARTING_REGION`, 233 → 235) — type count
  unchanged because the `runId` field is on the existing `GameState`
  shape rather than a new top-level type; Phase 73 added two codex
  types (`CodexEntry`, `CodexState`, 165 → 167). Tag shipped at
  235 + 167.
- `[unreleased]` (post-Phase-75 + Phase-76): Phase 75 added one
  runtime export (`previewTemplateAtRarity` — UI-tier wrapper
  around `dropItem` for mobile item-library mod-visibility,
  235 → 236); Phase 76 added one more (`previewTemplateAtAllRarities`
  — batch wrapper around the Phase 75 single-cell helper for UI
  tooltip / item-detail rarity-strip views, 236 → 237). Types
  unchanged (both helper signatures use existing `ItemRarity` /
  `Equipment`). Ships with the next bump at 237 + 167.

Phase 72 was the first runtime-export-count change in the 0.10.x
line; Phase 75 is the second; Phase 76 is the third. Type-export
count grew across Phase 60 / 66 / 68 / 71 / 73.

## When to add a new tool here

Drop a new `.mjs` at `scripts/` root when it:

- Enforces a structural contract that the deploy gate should fail on
  (extend `deploy-check.mjs` rather than adding a sibling unless the
  new check has a distinct CLI entry point — e.g. the
  `diff-public-surface.mjs` sibling).
- Is a release-engineering tool consumed by `RELEASING.md` or by the
  autonomous loop's `/march` flow.
- Doesn't need to ship in the published package (the npm `files`
  field covers `dist/` only — anything in `scripts/` is dev-only by
  design).

Add a row to the **Tools** table above. If the new check belongs in
the deploy gate, also extend `deploy-check.mjs` with the assertion
+ the failure message that names the canonical fix (`automation/README.md`
+ this README are the model for failure-message UX — name the file the
contributor needs to touch).
